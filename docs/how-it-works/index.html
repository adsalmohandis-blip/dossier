How it works

Record it while it happens, not the week before the audit.

Dossier sits beside your build. It watches nothing and scans nothing. You tell it what the agent did, it reads the reports your tools already produce, and it keeps a log where changing one entry breaks every entry after it.

One release, start to finish

Seven commands. Each one appends to the log and nothing ever rewrites it.

# once, in the repository you already have
$ npx dossier-cli init

# while the agent works
$ dossier task start T-1 \
    --title="Read the sensor over I2C" --model=claude-opus-5
$ dossier task end T-1 --files=src/sensor.c,src/sensor.h

# the decision that will be questioned two years from now
$ dossier adr add --id=ADR-001 \
    --title="Poll instead of interrupt" \
    --context="..." --decision="..." --status=accepted

# read the reports your build already wrote
$ dossier gate run
$ dossier approve --actor=eng.lead --release=v1.0.0

# the file, the record and the receipt
$ dossier bundle --release=v1.0.0
$ dossier receipt .dossier/bundles/v1.0.0.json \
    --org="Your company"

Run dossier gate run before approval and it will refuse the bundle and name the step that is missing. That refusal is the product.

The gates read other tools. They never re-run them.

What a gate is

  • static_analysis reads a cppcheck XML report against a limit you set
  • coverage reads an lcov file against a minimum you set
  • binary_size measures a built artifact against a ceiling
  • human_approval requires a named person and a date

What a gate will not do

  • Analyse your code. It reads the report your analyser wrote.
  • Pass because a report is missing. A missing report is recorded as skipped.
  • Be overridden quietly. Forcing a bundle past a failed gate is recorded in the bundle.
  • Phone anything home. Every gate runs against a file on your disk.

Why editing the log is noticed

Every entry carries the hash of the entry before it. Change a coverage number in event four and event five no longer points at anything that exists, so the chain is broken at a named position. The bundle refuses to build on a broken chain, and a bundle that has already been built stops matching its own hash.

This is not a clever trick, and it is not a blockchain. It is the oldest property of a hash: the same input gives the same output, and a different input does not. The adversarial tests exist to prove it, by tampering on purpose and asserting that verification fails.

The permanent link, and the code that points at it

A receipt is one self-contained page: no scripts, no fonts fetched, no network calls, so it still works when someone opens it from a folder years from now. The QR code is drawn by Dossier itself rather than by a web service, because a tool that promises nothing leaves your machine cannot quietly send your hashes to someone else's server to have a picture made.

Generating a receipt is free and local. Hosting it at a link that stays up, and signing it, is what the Team plan is for. Receipts already issued keep working whether or not you are still paying: holding a customer's compliance hostage is not a business we want.

What we can see, which is nothing

Dossier has no telemetry, no account and no network code. We cannot count installs, read your gate results or tell whether you are using it at all. A tool that reads the output of your analyser has no business reporting it to anyone, and the source is open so you do not have to take our word for it.

That leaves us with no way to learn what is worth building, so there is one command for it, and it is entirely yours to run or ignore: 

$ dossier report

It writes a single file of counts — which gates you turned on, how many passed, which toolchain it found, how many decisions you recorded — prints every line to your terminal before writing it, and sends nothing anywhere. No file names, no hashes, no company or product names, no coverage figures, no names of people who approved. Read it, and mail it to us only if you are happy with what it says.

The report is built from a fixed list of numbers rather than by filtering your log, so a field added to Dossier in some later version cannot find its way into one by accident. A test asserts exactly that.

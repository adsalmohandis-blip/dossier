Your firmware is now a product under strict liability.

The EU Product Liability Directive treats embedded software as a product, and the defence that a defect appeared after sale does not apply when the cause is software or a missing update. Your coding agent writes that software. Dossier records what it wrote, which gates it passed and who approved it — and produces the file you hand to an assessor.

# in your firmware repo
npx dossier-cli init
npx dossier-cli task start T-1 --title="add sensor read" --model=claude-opus-5
npx dossier-cli approve --actor="eng.lead" --release=v1.0.0
npx dossier-cli bundle --release=v1.0.0

A gate whose report is missing is recorded as skipped, never as passed. Silence is not evidence.

What it does not do

  • It does not generate code. Your agent does that.
  • It does not analyse code. cppcheck and friends do; Dossier reads their reports.
  • It does not build SBOMs. Zephyr emits SPDX; Dossier links it.
  • It does not grant certification. A notified body does; Dossier prepares what they ask for.
  • It does not touch the network. No telemetry, no accounts. Your code never leaves your machine.

Tamper with it and it says so

The event log is append-only and hash-chained: every entry carries the hash of the one before it. Rewrite an entry, delete one from the middle, or change a byte of a finished bundle, and verification fails and names where.

npx dossier-cli verify .dossier/bundles/v1.0.0.json
VERIFIED — bundle matches its hash.

These checks ship as public tests in the repository, so you can read them before you trust them.
